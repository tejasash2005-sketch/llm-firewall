# eBPF and daemon failure-mode matrix

This matrix describes the implementation in `firewall_kernel.bpf.c`,
`src/kernel_loader.rs`, `src/main.rs`, and `src/proxy.rs`. “Fail-open” means a connection
may reach its destination without proxy inspection; “fail-closed” means it is blocked. The
current transparent mode is best-effort and is not fail-closed. A kernel firewall rule that
denies direct egress is needed if bypass must be prevented.

| Scenario | Current behavior and detection | Security behavior | Existing coverage | Change / remaining gap |
|---|---|---|---|---|
| eBPF object or required kernel resource missing | `KernelFirewall::load` reports contextual errors for object, maps, programs, cgroup, and attachments. Startup returns an error. Missing-object test verifies the object-load failure before attach. | Startup fails; with no successfully attached hooks, direct traffic is fail-open. | `missing_ebpf_object_fails_startup_before_kernel_attachment`; no test for every missing map/program. | Keep startup failure explicit. Real resource/attachment failures need Linux privileges and are unverified here. |
| Insufficient privileges to load/attach | Aya load/attach errors propagate with context; startup exits. If one hook attached before the next fails, Aya-owned link handles are dropped with the `Ebpf` value. | Any hooks detached on process exit leave direct egress fail-open. | No privileged test. | No code change. Partial-attachment cleanup and kernel detach behavior are unverified on a privileged Linux host. |
| Kernel/eBPF initialization failure | Object/map/program loading, cgroup open, attach, and initial target seeding return errors; `main` exits before serving. The configured target addresses are seeded after attachment. | Startup failure is fail-open outside any surviving attached hook; process cleanup is relied on. | Missing-object test only. | No code change. Exercise attach/map failures on supported Linux kernel in deployment validation. |
| Daemon fails during startup | `main` propagates CA, listener, BPF setup, and initial DNS seeding failures. When startup unwinds, owned resources drop. | No proxy service; transparent connections are fail-open if hooks are absent/detached. | Missing-object loader test; no whole-process startup test. | No change. External service management and egress policy determine recovery/security. |
| Daemon exits unexpectedly after startup | Links and maps are process-owned and not pinned; process teardown is expected to detach hooks. No independent supervisor is built in. | Direct traffic may bypass inspection (fail-open). | No process-crash integration test. | Documented limitation; external egress deny is required for fail-closed behavior. Kernel teardown is not tested here. |
| Heartbeat is stale or stops | There is no heartbeat map or stale-heartbeat detector. A returned error, panic, cancellation, or unexpected normal completion of the eBPF task is observed by `supervise_kernel`; a task that hangs is not. | On detected task exit, proxy acceptance stops, but hook detachment can still permit direct egress. A hung task may leave proxy running without event/refresh progress. | `kernel_error_stops_proxy_future`, `kernel_task_panic_stops_proxy_future`; no hang/heartbeat test because no heartbeat exists. | Do not claim hung-task detection. Heartbeat/pinned-link fail-safe mode remains future work. |
| Kernel-to-userspace delivery fails or is overloaded | Ring buffer is 1 MiB and audit-only. BPF reservation failure increments a per-CPU drop counter and preserves redirect decisions. Userspace drains at most 256 records per turn; readiness is retained if the budget is exhausted. AsyncFd/read or counter-read failures are logged/returned as applicable. | Audit loss does not change redirect policy. A fatal ring task error is detected and proxy acceptance stops; subsequent direct egress remains possible after detach. | `audit_drain_budget_preserves_remaining_records_for_the_next_turn`; no real ring-overload test. | No behavior change. Actual ring pressure and kernel-to-userspace failures require privileged integration testing. |
| Audit record truncated, malformed, or unsupported family | Exact record length and AF_INET/AF_INET6 are required. Invalid records are warned and discarded; they do not feed policy. | Redirect decision is independent of audit decoding; malformed audit data does not open a connection path. | `rejects_short_audit_records`, `rejects_oversized_and_unsupported_audit_records`. | Implemented strict decoding; padding/content validation beyond length and family is not required by current record layout. |
| Policy state missing, stale, or inconsistent | BPF allows when config is absent/port is zero, caller is proxy PID, or destination is absent from target maps. `refresh` adds DNS results but never evicts; refresh errors retain the old set. Map-cap overflow warns and skips addresses. | Missing/new target entries are fail-open. A stale old IP may still redirect a now-unrelated endpoint; proxy allow-list/SNI checks reject unapproved hosts. | No deterministic BPF map-state unit test; proxy host rejection has existing tests. | No global fail-closed change. Target-map lifecycle and DNS behavior need operational monitoring; explicit proxy mode or external egress controls narrow bypass. |
| Shutdown while events or requests are in flight | Proxy stops accepting and waits up to five seconds for connection permits; it warns if work remains. Main signals the kernel task and awaits it; BPF task reports drops and returns, dropping links. | Existing in-flight requests may complete during drain or be cut off after timeout. After detach, direct egress is fail-open. | `proxy_shutdown_is_forwarded_to_kernel_task`; no active-request drain integration test. | No change. A process kill cannot guarantee graceful drain. |
| Cleanup sees already-removed kernel resources | Cleanup is via owned Aya objects/link handles; there is no explicit resource-removal loop or custom retry. The result of kernel-side detach after external removal is not established by unit tests. | Unknown for externally removed links until verified; process-owned resources should be dropped, but kernel-specific outcomes are not asserted. | None. | Marked unverified; do not assume idempotence for externally removed links. |
| Proxy or daemon restarts after failure | There is no internal restart loop. A supervisor/operator must restart the process. On a new start, maps and links are loaded anew and target addresses reseeded. | Fail-open interval can persist until hooks are attached and targets seeded; external egress policy is required to close it. | Supervision helper tests error/panic shutdown only; no process restart test. | No automatic restart feature added. Validate service-manager policy and startup ordering in deployment. |

## Enforcement and platform limits

The cgroup hooks inspect TCP/443 connect calls for IPs currently in target maps. They do not
block connections: missing config or target entries return allow, and audit is observational.
The proxy is exempt by PID to avoid redirect loops. There is no heartbeat, pinned-link
supervision, or kernel-side fail-closed guard. Stopping the proxy after detecting an eBPF task
exit reduces continued use of the proxy in a degraded process, but is not a substitute for an
external egress-deny policy.

The source requires Linux, a cgroup v2 attach point, BPF/networking privileges, and a kernel with
ring-buffer support (Linux 5.8+ per README). Userspace tests exercise parsing and supervision
without loading privileged programs. No claim is made here that attachment, kernel cleanup,
ring-buffer overload, or real bypass behavior has been verified on a privileged kernel.
